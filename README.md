# Daylatch Home OS

Daylatch — Homepage UI/UX Redesign Brief
You are designing the new homepage for Daylatch, an AI-powered household operating layer.

Product North Star

Everything in the design must support this north star:
Daylatch knows what matters to your household.
It knows who owns it.
It knows when it matters.
It prepares what needs to happen.
And it never acts without your permission.
Daylatch is not simply:

an AI chatbot

a reminder app

a task manager

a document manager

an email inbox

a family calendar

Those are components.
The larger product vision is:
Daylatch is the operating layer for modern households.
It continuously turns the scattered administrative work of everyday life into understandable responsibilities, next steps, coordinated ownership, and eventually approved actions.

Core Product Philosophy

The experience should communicate:
Life happens → Daylatch understands → Daylatch organizes → Daylatch coordinates → Daylatch prepares → Human approves → Daylatch acts → Daylatch remembers
The user should feel:
“My household is under control.”
Not:
“I have another productivity app to manage.”
This distinction is critical.

Existing Website

There is an existing Daylatch website:
daylatch-6.polsia.io
Review the existing design before making changes.
The existing visual language is intentionally:

clean

minimal

calm

modern

trustworthy

spacious

consumer-friendly

AI-native without looking overly technical

The current experience also contains the important concept of:
Paste something → understand it → know what to do next
Do NOT throw away this interaction.
Instead, evolve it into the larger Daylatch vision.
If the existing design system is good, reuse it.
Do NOT rebuild from scratch merely for the sake of redesigning it.

Primary Homepage Objective

The homepage should immediately answer four questions:

What is Daylatch?

An intelligent operating layer for household administration.

What problem does it solve?

It keeps track of what the household needs to remember, decide, assign, and get done.

How does it work?

Give Daylatch the things that arrive in everyday life — messages, bills, forms, receipts, appointments, documents, etc.
Daylatch turns them into:

responsibilities

deadlines

owners

next steps

reminders

prepared actions

Why should I trust it?

AI can prepare and recommend, but nothing sensitive happens without the user's approval.

Create a strong, premium hero.
Preferred headline direction:
Life asks. Daylatch handles.
Supporting copy:
The operating layer for your household.
Bills, forms, appointments, documents, renewals, deadlines and everyday responsibilities — Daylatch keeps track of what matters, who owns it, and what needs to happen next.
Primary CTA:

Avoid phrases such as:

The product should feel calm, capable and trustworthy, not hype-driven.

The Key Concept: Responsibilities

Do not make Daylatch feel like a conventional task manager.
A task is:
Buy milk.
A Daylatch responsibility is:
Keep the household's car insurance current.
That responsibility may contain:

policy document

expiry date

renewal quote

owner

reminder

comparison

approval

payment

confirmation

Design the UI around responsibilities, not just tasks.

Show Ownership

One of Daylatch's differentiating concepts is:
Who owns it?
Show this visually.
Example:
Car insurance renewal
Owner: Dad
Due: Sep 14
Status: Needs decision
Another:

Owner: Mom
Due: Tomorrow
Status: Signature required
The household should feel coordinated rather than merely organized.

Show “Waiting”

Traditional task apps usually think:
To Do → Done
Real household administration is:
Received → Understood → Assigned → In progress → Waiting → Follow-up → Done
Create a subtle but visible “Waiting” state.
Example:
Waiting
Insurance provider
Response expected Sep 3
School
Confirmation pending
This is an important part of the product because Daylatch should eventually remember things people would otherwise forget.

Show the Approval Principle

Create a section communicating:

Possible supporting copy:
Daylatch can understand, organize and prepare the work. You remain in control of sensitive actions.
Show a simple progression:
Understand
→ Prepare
→ Ask
→ Approve

Never imply that Daylatch will independently make sensitive decisions.
Avoid language suggesting uncontrolled autonomy.

Do Not Overbuild the Homepage

The homepage should NOT try to explain every future capability.
Do not add:

banking integrations

payment integrations

browser automation

50 feature cards

complicated AI architecture

long technical explanations

huge competitor comparison tables

The homepage sells the vision and core experience.
The application can progressively deliver the deeper functionality.

Important Product Architecture Principle

Design the UI so that future features can be added without redesigning the entire product.
The underlying conceptual model should support:
Household
→ People
→ Responsibilities
→ Documents
→ Events
→ Deadlines
→ Sources
→ Actions
→ Approvals
→ History
The homepage should be the calm surface over that deeper system.

Responsive Design

Design for:

Desktop

Tablet

Mobile

Mobile should NOT simply be a compressed desktop dashboard.
On mobile, prioritize:

Needs attention

Next steps

Waiting

Upcoming

Send something

The product should work naturally alongside WhatsApp.

Final Design Test

Before considering the homepage finished, evaluate it against these questions:
Can a visitor understand Daylatch in 5 seconds?
Does it look different from a generic AI chatbot?
Does it look different from a task manager?
Does it communicate household coordination?
Does “who owns it?” appear naturally?
Does “when does it matter?” appear naturally?
Does “what happens next?” appear naturally?
Does the approval-first trust model feel obvious?
Does the product feel useful before the user has uploaded anything?
Does it look like something a household could eventually depend on every day?
If the answer to these questions is yes, the homepage is working.

Most Important Instruction

Do not design Daylatch as a collection of AI features.
Design it as a new product category:
The operating layer for household administration.
The UI should make that idea feel inevitable.
Use the existing Daylatch design wherever it already supports this vision. Improve and evolve it rather than rebuilding merely for visual novelty.
The goal is not to make a prettier landing page.
The goal is to make someone see Daylatch and immediately understand:
“This knows what my household needs to deal with.”
“It knows who should handle it.”
“It knows when it matters.”
“It can get the work ready.”
“And it won't do anything important without me.”
That is the Daylatch product.
